# tester memory

Lessons learned across stories. One rule per line, newest last. Keep under 100 lines.

- Start e2e specs with `/// <reference lib="dom" />` because `e2e/` is typed by tsconfig.node.json (no DOM lib) and `page.evaluate(() => window…)` otherwise breaks `npm run typecheck` (story 001).
- Run `npm run verify` (not just vitest/playwright) after writing e2e: typecheck covers `e2e/` and only verify catches it (story 001).
- Assert "focus left the page" with `document.activeElement === document.body`, not `locator('body').toBeFocused()`: Tab past the last stop moves focus to browser chrome and body reports inactive (story 001).
- Drive the e2e fake via `page.evaluate(() => window.__fakeGoogle?.settleSignIn(...))`; poll in `beforeEach` that `__fakeGoogle` exists so specs can't silently run against real Google; call `setAccount` after each goto/reload (story 001).
- Integration pattern that works: real `App` + `AuthProvider` + `createGoogleAuthClient({loadScript, fetchFn})` with stubbed GIS gives AC coverage for real error mapping without a browser (`src/app/App.google.test.tsx`, story 001).
- Use `vi.stubEnv('VITE_GOOGLE_CLIENT_ID','')` to test the missing-client-ID path; stub `console.error`/`warn` (provider warns in DEV) to keep output clean (story 001).
- Layout checks at the 600 px breakpoint via bounding boxes + `scrollWidth > clientWidth` are stable in Chromium; use `test.use({ viewport })` in a describe block (story 001).
- Probes worth repeating on UI-with-async-state stories: double click, settle twice, reload while pending, rapid repeated failures, hostile text (`<img onerror>`), very long strings, keyboard-only with Enter and Space (story 001; none found a defect there).
- For timeout logic use `vi.useFakeTimers()` after `await setup()` (setup flushes with a real setTimeout) and `advanceTimersByTimeAsync`; in component tests wrap in `act(() => …)` (story 001 round 1).
- Add boundary tests for timeouts (answer at limit-1 succeeds, limit fails, timer count 0 afterwards) and a stale-response-vs-next-attempt race test (story 001 round 1).
- Keep tests minimal when hak asks (story 004): one test per AC or AC group at one level, skip what developer unit tests cover, run probes as throwaway specs (write in e2e/, run, delete) and list them as "checked, OK" unless they found a defect or real risk.
- A temp spec in e2e/ can probe a `vite preview` production build via an absolute URL (start `npx vite preview --port N` in background, kill after) (story 004).
- Mutation-check build guards by appending the forbidden string to dist/assets/*.js and re-running `npm run check:dist`, then rebuild (story 004).
- Real touch long-press in Chromium: `test.use({ hasTouch: true })` + `page.context().newCDPSession(page)` + `Input.dispatchTouchEvent` touchStart / wait / touchEnd; `locator.tap()` for a short tap. Catches long-press-plus-click/contextmenu double actions better than dispatched pointer events (story 005).
- Query ARIA-grid cells whose accessible name changes with state by prefix regex (`^Row 3, column 5,`) and assert state with `toHaveAccessibleName`; `page.locator(':focus')` + `toHaveAccessibleName` checks roving focus (story 005).
- Enter inside a form field leaves focus in that field; "focus stays on Start" only holds after clicking Start. Don't assert Start focus after Enter-submit (story 005).
- Fixed-layout hooks (`window.__minesweeperMines`): convert 1-based test coordinates to 0-based in one helper; layout length must equal the mine count or the reducer throws (story 005).
- When a feature removes UI that older specs name (counter), grep `e2e/` for the old strings and also look for assertions that now pass vacuously (`toHaveCount(0)` on a gone element) (story 005).
- Forced-colours probes: `page.emulateMedia({ forcedColors: 'active' })` applies `@media (forced-colors)` rules at once; in Chromium `ButtonFace` resolves to white like Canvas, so compare the inset `box-shadow`/border, not the background (story 005 round 1).
- Before comparing "hidden" vs "revealed" styles in a grid probe, read the accessible name of the sample cell and pick one a flood fill cannot open; a fixed layout with corner mines wins after one reveal and flags every mine (story 005 round 1).
- Fake clock for timers: `page.clock.install({ time })` before `goto`, sign in, then `pauseAt(time + 60 s)`; works with the sign-in fake and guest login, no hook needed. Use `fastForward` for huge jumps (`runFor` of 1e6 s fires 4M ticks, 20 s) (story 006).
- The `__minesweeperMines` hook persists across Starts on the same page: `delete window.__minesweeperMines` before a start with another mine count, or the reducer throws and the board never renders (story 006).
- Compare layout claims in the UX design (e.g. "three buttons in one row at 375 px") with bounding boxes at 320/375/800; flex items with `min-width:auto` break them (story 006). Keep a layout defect as `test.fixme` so the suite stays green.
- Adding a new tab stop before existing ones (presets before Rows) breaks keyboard specs in `e2e/auth.spec.ts`; grep for `Tab` sequences when UI is added above the form (story 006).
- Keyboard specs must not name controls of another feature: to step past a control assert `not.toBeFocused()`, then return with `Shift+Tab` and assert focus again; this stays valid when layouts change (auth.spec.ts keyboard sign-out test, fixed after stories 005/006).
- CSS-module class names are hashed in the dev server: inject-CSS mutation checks must select by role/attribute (`div:has(> [role=grid])`, `[role=gridcell]`), not `.scroller`/`.hidden` (story 007).
- Cells transition `box-shadow`/background for 120 ms: before reading computed styles of cells, `expect.poll(() => page.evaluate(() => document.getAnimations().length)).toBe(0)`, otherwise "hidden vs empty" signatures flake (story 007).
- A fixed layout with a wall of mines (column 3 of a 5 x 5) lets one click open a region and leaves hidden, flagged, wrong-flag, mine and exploded cells all visible after a loss (story 007 `loseWithAllStates`).
- Chromium's `forcedColors: 'active'` emulation draws `GrayText` dark red; reddish thin borders there are not a bug (story 007).
- Screenshot runs: wait ~400 ms after a state change; the mouse still hovering a button makes it look "hover-coloured" in the shot (story 007). Gate-2 shots: throwaway spec in e2e/, output to `test-results/<story>/` (gitignored), delete the spec.
- When an old spec pins a replaced visual spec (colour, px), check the story ACs first: if they don't mention it, rewrite to the intent (focus ring >= 2 px solid and not transparent; button width == its container) instead of new magic numbers (story 007).
- Playwright wipes `test-results/` on every run: write screenshots (or any artefact meant to outlive the run) to `screenshots/<story>/` (gitignored) and run the e2e suite BEFORE taking them (story 007).
- "X equals its container" checks prove nothing when the container is the element's own flex wrapper; compare with an ancestor's content box (clientWidth minus padding) (story 007).
- For forced-colours cell checks assert glyph paint != backdrop (fill/stroke resolved) rather than comparing markup; markup always differs even if the glyph is invisible (story 007).
- Never compare two screenshots with `Buffer.equals` after a CSS transform was applied and removed: raster noise (<= 2/255 on rounded edges) makes it fail; decode both PNGs in the page (canvas getImageData) and count pixels above a per-channel tolerance (8) (story 008 `differingPixels`).
- Replace "Tab once from X to reach the board" by a bounded loop (`for i<12 && no :focus in grid: press Tab`) so new controls above the board don't break old specs (story 008).
- Bounding boxes of cells under a CSS perspective/rotateX include the slant (32 px cell reports 33 px); don't pin exact widths of 3D cells, and `box-shadow !== none` no longer tells hidden from revealed there (story 008).
- A second Playwright project with `testMatch` + `grep: /AC(6|8):/` plus a `beforeEach` on `test.info().project.name` re-runs existing flows in another mode without duplicating bodies (story 008 `chromium-3d`).
- To probe an old spec in a new mode, copy it to e2e/zz-*.spec.ts, add the mode switch to its sign-in helper, run, delete (story 008 forced colours in 3D).
- Capability fallbacks: `page.addInitScript(() => { CSS.supports = () => false })` before goto works with the dev server (story 008 AC7).
- Computed box-shadow/background of cells read right after a view switch can still be mid-transition (120 ms): `expect.poll(getAnimations().length).toBe(0)` before comparing 2D vs 3D values, or the test flakes (story 008).
- Probe-paused scene frames: right after a state change the scene is at p=0 of its animation; call `probe.advance(2000)` before reading pixels, and anchor sampling to whole canvas pixels and the DOM cell box, not to `project()` of a cell whose level changes (hidden/revealed top moves ~3 px) (story 009).
- A sine sway is symmetric: two arbitrary times can show the same angle (2000 ms and 5000 ms of a 14 s period). Restart at phase 0 (`holdSway(true)` then `false`) before "frames 3 s apart differ" (story 009).
- Read a DOM box and a canvas projection in ONE `page.evaluate`; two round trips right after `scrollIntoViewIfNeeded` gave a 4.5 px false misalignment (story 009).
- Rendered pixels differ from tokens in lit scenes (dark glossy tiles rendered 2.5x brighter than the token): check glyph contrast on rendered pixels against the tile's own nearby top, not against a token or another tile (story 009 D1).
- Compare whole frames with `canvas.toDataURL()` hashed in the same task as `probe.advance()`; works without preserveDrawingBuffer (story 009).
- Mutation runs: back up `src/` first (not a git checkout of the tester's concern), script `old -> new` replacements with a restore in `finally`, diff against the backup after; a mutant that survives usually means the sample is too coarse (pole hid a missing cloth: filter by red hue) (story 009).
- Headed gate-2 stills/video: throwaway `scripts/zz-*.mjs` with `chromium.launch({headless:false})` and own vite on a spare port; `recordVideo` has no pointer, inject a fixed-position dot via `addInitScript`; trim with `/opt/homebrew/bin/ffmpeg -ss ... -t 29.9` and pad ~1.5 s before the scripted start (video clock lags) (story 009).
- Clicks outside the viewport do nothing in a scripted video (board below the fold): scroll first; a fixed layout must have exactly the preset's mine count; a layout whose mines are all in one block wins on the first cascade (story 009).
- macOS has no `timeout`/GNU `sed -i`; use `sed -i ''` or python for edits (story 009).
- Monorepo (story 011): run workspace probes from the root with `-w apps/<name>`; prove "only this app" by grepping the log for the other app's name. Plant failing tests prettier-formatted, else `format:check` fails first and the probe proves nothing.
- Count e2e before/after a restructure: `git archive main | tar -x -C scratch`, symlink node_modules, `npx playwright test --list`, diff sorted titles with file:line stripped (story 011).
- `rsync` a repo copy for scratch runs with `--exclude /apps/*/dist` anchored; an unanchored `--exclude dist` strips `node_modules/**/dist` and breaks every package (story 011).
- Throwaway app probes (`new-app.mjs zz…`): save `package-lock.json` first; npm leaves an `extraneous` `apps/<name>` entry after `rm -rf` + `npm install`, restore the saved lockfile (story 011).
- Dev-server probe of a non-e2e mode: `.mjs` in scratchpad with `createRequire('<repo>/package.json')('@playwright/test')`, guest button, then `pkill -f vite` (story 011).
- Prove "effect is really drawn" with token-coloured pixel counts: read `--scene-*` custom properties from :root in the page, `canvas.toDataURL()` in the same task as `probe.advance`, decode via `Image.decode()` + 2D canvas, count pixels within tol 40; baseline against the FINAL board (flags are red like a confetti token), not the pre-click board (story 010).
- Flash rule for an e2e: probe `luminance()` series (33 ms first second, then 100 ms) on whole canvas, 341x256 window and 150 px around the origin; swings >= 10 % of the brighter value via zigzag with 5 % hysteresis; unit-test the counter with a strobe/pop/wobble self-test; mutate with a full-screen `scene.overrideMaterial` white strobe (a bloom-only strobe hides under the fireball in light) (story 010).
- Mutation runner pattern: python script with a dict of (file, old, new) replacements, backup of `src/` in scratchpad, run the spec with `--grep-invert` for slow tests, restore in `finally`, `diff -r` against backup (story 010). Mutating the scene-only code path (e.g. markerPose) does not hit reduced-motion static drawing; mutate the static branch instead.
- In a real-loop (unpaused) 3D page Playwright `click`/`scrollIntoViewIfNeeded` wait forever for "stable" because of the sway: use keyboard (focus + Enter), `force: true`, or `boundingBox` + `mouse.click` (story 010 probes, video script).
- `page.clock.install` + `pauseAt` works together with the paused probe: scene time stays manual, `runFor` moves only the timer; use it to assert "timer frozen while scene clock still at 0" (story 010).
- Gate-2 stills: `page.screenshot({fullPage:true})` or the board is below the fold at 375 px; `recordVideo` runs leave one webm per run in the dir (pick the newest, `head -1` picked a truncated one); ffmpeg libx264 mp4 is available at /opt/homebrew/bin (story 010).
- measure:fps can show a one-off input-latency outlier (112/211 ms) on the first run after idle; re-run once, a clean second run is the figure to report (story 010).
- A real-loop check that only asserts "idle after N s" is vacuous for "plays" (also idle when cut after one frame): assert running at the first frame AND that the first idle frame is >= the effect's own end; take time zero from a MutationObserver on the result message, not from a Playwright round trip (story 010 review finding 1/6).
- Real-clock 3D tests on SwiftShader: do a warm-up game first (first end pays 1-2 s of one-time cost), use a 375 px viewport, `retries: 2` on that describe (parallel workers stall frames), and after writing a mutation to src sleep ~4 s so the dev server serves it (an unsettled run passed a mutant once).
- Emulate a hidden tab with `Object.defineProperty(document,'hidden',{configurable:true,get:()=>true})` + dispatch `visibilitychange`; remove with `Reflect.deleteProperty` (story 010).
- Process/script stories (012): drive check-structure rule probes with a generator script (python writes N scratch stories + index into a scratchpad dir with a copied `scripts/`); compute expected sums with a calculator first, my own wrong total cost one round. Probe loosened matches (`startsWith` accepted 10x the sum) and unchecked columns, not only the planted cases.

- Chart series check: screenshot the `role=img` chart, decode in page, count pixels near each `--chart-*` token; a bare "screenshot changed" test survives a mutant that drops one series (story 013).

- Choose inputs that actually move the oracle: monthly 200 EUR hits the 1.800 EUR deduction cap so refund/reinvested stay 3.099,60; use 100 EUR for "update on input change" (story 015).
- A pixel check on a framed+striped series survives a mutant dropping only the stripes; mutate by omitting the segment (story 015).
