# developer memory

Lessons learned across stories. One rule per line, newest last. Keep under 100 lines.

- Type optional pass-through props as `prop?: T | undefined` (className, refs) because CSS-module classes are `string | undefined` under `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` and tsc fails otherwise (story 001).
- Don't use `Promise.withResolvers` (ES2024; tsconfig lib is ES2023); use `src/lib/createDeferred.ts` (story 001).
- Run `npm run typecheck` (root has no tsconfig, so plain `npx tsc --build` there fails) after every new component, not only after tests: vitest passes even with type errors (stories 001, 014).
- When grepping `dist` for a code path behind a `VITE_*` var, build once with the var set: unset vars are inlined as `undefined` and Vite drops the whole branch (story 001).
- Test `import.meta.env` guards with `vi.stubEnv('MODE', 'e2e')` / `vi.stubEnv('DEV', false)` + `vi.unstubAllEnvs()` in afterEach (story 001).
- For ad-hoc browser checks, start `npx vite --mode e2e --port 5174` in the background and run `node --input-type=module -e "import { chromium } from '@playwright/test' …"` from the repo root; macOS has no `timeout` command; kill it (`lsof -tiTCP:5174`) before `npx playwright test`, which starts its own server on 5174 (stories 001, 005).
- Bound every non-interactive network call (fetch + body read) with AbortController + setTimeout (named constant) and a Promise.race fallback, because reviewers flag a UI that can hang in a progress state as major (story 001).
- In adapters with fixed callbacks (GIS), track a per-attempt flag/identity so late callbacks for an already-decided attempt are ignored (story 001).
- For fake-timer tests, finish async setup with real timers first, then `vi.useFakeTimers()` and `await vi.advanceTimersByTimeAsync(...)` (wrapped in `act` for components); `vi.useRealTimers()` in afterEach (story 001).
- When `AuthUser` (or any shared type) becomes a union, fix test literals with a targeted sed (e.g. `{ id: '` → `{ provider: 'google', id: '`) and then grep multi-line literals, because `toEqual` failures only show at runtime, not in tsc (story 004).
- Keep the test set minimal when the design names one (hak found 001 test-heavy): add only the listed unit/provider cases, and leave e2e-covered UI to the tester (story 004).
- To give stacked buttons equal width without stretching them, wrap them in an `inline-flex` column and switch to `flex` below 600 px; 001 e2e checks that the Google button is <300 px wide (story 004).
- Remove a computed key from an object with `Object.fromEntries(Object.entries(o).filter(...))`, because tseslint strict forbids `delete o[key]` (no-dynamic-delete) (story 005).
- Type CSS custom properties in `style` as `CSSProperties & { '--name': number }` instead of an `as` cast (story 005).
- To focus the first invalid field with its error already in `aria-describedby`, run the submit callback in `flushSync` and then `querySelector('[aria-invalid="true"]')?.focus()` (story 005).
- Let content break out of the 40 rem `main` column by a modifier class that drops `max-width` (children re-apply it), not with `100vw` math, which overflows when a vertical scrollbar shows (story 005).
- Delete files with plain `rm`, not `git rm`, because `git rm` stages the change and agents leave staging to hak (story 005).
- In `@media (forced-colors: active)`, fills and `box-shadow` are dropped: give state cues that carry meaning `forced-color-adjust: none` + system colours, and check with Playwright `emulateMedia({ forcedColors: 'active' })` (story 005).
- Mount live regions empty from the start and make each announcement's text differ (e.g. a no-break space on alternate ids), because screen readers ignore regions inserted together with their text and unchanged text (story 005).
- Put a visually hidden description next to (not inside) a button that must have an exact accessible name, because hidden-by-clip text inside the button still counts toward the name (story 006).
- When a live region should be "mounted empty", don't append a no-break-space repeat trick to empty text: guard it with `text !== ''` / serial > 0 (story 006).
- A tab-order change in the UI breaks existing keyboard e2e specs (e.g. auth.spec.ts Tab after Sign out): run `npx playwright test` once at the end and report such failures to the tester (story 006).
- Vitest returns an empty string for `*.css` / `*.css?raw` imports: read CSS in tests with `node:fs` and `/// <reference types="node" />` at the top of that test file (story 007).
- BSD sed on macOS needs `sed -i ''`; for multi-line edits use a short python3 heredoc (story 007).
- Restyling a shared control (focus colour, button size/width) breaks old e2e visual assertions (e.g. `rgb(11, 87, 208)` outline): run `npm run test:e2e` once and report such specs to the tester instead of editing `e2e/` (story 007).
- To override a shared component's CSS-module class from a caller, use a two-class selector (`.wrapper .variantClass`) because import/bundle order of modules is not a reliable tie-breaker (story 007).
- Check layout numbers with a throwaway playwright script (scrollWidth, cell width, well scrollWidth) at 320/375/800 and look at one screenshot before reporting; UX design arithmetic can be off (story 007).
- A native radio/checkbox used as an invisible overlay needs `appearance: none` + `border-radius: var(--radius-control)` + `font: inherit`, because Chromium keeps the UA's `50%` radius and Arial otherwise and redesign.spec.ts AC2 checks every `input` for one radius and one font (story 008).
- Adding a control above the board pushes it ~70 px down: touch e2e specs that use `boundingBox()` + CDP touch fall off the 720 px viewport, and Tab-order specs gain a stop; report both to the tester (story 008).
- `lsof -tiTCP:5174` also lists client processes (Claude helper); use `-sTCP:LISTEN` to find a stale vite from an earlier stage and kill it before `npm run test:e2e` (story 008).
- CSS Modules only emit classes that exist in the stylesheet: `styles.empty` etc. are `undefined` until a rule names them; adding 3D rules for them is what makes them appear (story 008).
- Run ad-hoc playwright scripts with `node --input-type=module < /abs/path/script.mjs` from the repo root: a script in the scratchpad can't resolve `@playwright/test` (story 008).
- Playwright `click()`/`scrollIntoViewIfNeeded()` never see a continuously transformed (swaying) element as "stable" and time out: pause the motion first, or click by coordinates from an in-page `getBoundingClientRect()` (story 009).
- react-hooks v7 lint rejects `setState` in an effect body and reading `ref.current` during render: announce state transitions with the render-time "adjust state when a value changes" pattern (compare with a `useState` copy of the previous value) and keep objects the render needs in `useState`, not refs (story 009).
- The token test only allows `border-radius: var(--radius-*)`, `transition` with `var(--duration)` or `0s`: for a derived radius define a module custom property `--radius-x: calc(...)`; use `transition-duration: 0s` instead of `transition: none` (story 009).
- `@media not (a) and (b)` is invalid and fails the lightningcss build; write `@media (not (a)) and (b)` (story 009).
- A fit factor on a fluid cell size must apply to the whole grid width incl. gaps (`(avail / fit − gaps) / cols`), otherwise the board overflows by `gaps · (fit − 1)` (~1 px scrollbar); measure scrollWidth vs clientWidth at 320/375 (story 009).
- Calibrate 3D look numbers by sampling rendered pixels (probe) in BOTH colour schemes, not by formula: a design's shadow ratios ignored gaps/bevels, and gloss/env reflections that are harmless on a light tile lifted the dark tile ~2.5× and broke glyph contrast (tester defect D1) (story 009).
- Wrapping a component's root child in a new element (e.g. a stage around the grid) breaks e2e helpers that use `el.parentElement`/`locator('..')`, also in other stories' specs: grep `e2e/` for `parentElement` and `'..'` and report them (story 009).
- Every inline style a render loop writes (transform, size) must also be written where layout is measured (attach/update/resize), because the loop doesn't run in forced colours, reduced motion or before the first rAF — reviewer major (story 009).
- A pixel/size floor tied to an AC must be tested at the strictest geometry (far edge, extreme aspect ratio, full sway) with the floor read from tokens.css, not a softer proxy like the centre line (story 009).
- In a workspace, `prettier --check .` reads only the cwd's `.prettierignore`: use `--ignore-path ../../.prettierignore`, else `dist/` and `test-results/` fail the check (story 011).
- `/// <reference path>` in a platform barrel fails `@typescript-eslint/triple-slash-reference`: include the `vite-env.d.ts` in the app's `tsconfig.app.json` instead (story 011).
- Test-only helper modules that use `node:fs` need `/// <reference types="node" />` at the top, since the app tsconfig has no node types; export them through the `./test/*` exports entry (story 011).
- A signed-in marker for shared e2e specs must be visible right after sign-in (Minesweeper: the `Start` button, not the board grid, which appears after Start) (story 011).
- Do the moves with `git mv` in one shell chain and double-check temp names: a typo'd target dir creates junk that needs another `git mv` back (story 011).
- Look at a rendered still before calibrating any effect: probe counters (`fxState.particles`) were non-zero while nothing was drawn (counts reset by another loop, culled faces, objects hidden at compile time) (story 010).
- three's `renderer.compile` only walks visible objects: keep pre-warmed meshes visible for the compile and hide them right after it, else the first use compiles (story 010).
- Hand-built index buffers must wind counter-clockwise seen from the camera, or the faces are back-face culled with no error (the shock ring was invisible) (story 010).
- Additive blending clips to white on light surfaces: pick additive vs normal blending from the palette (surface luminance) so fire and flashes read in both schemes (story 010).
- Don't add a frame-gap watchdog to clock-based (closed-form) animations: slow frames on SwiftShader/phones (500+ ms each) kill them; end them on `visibilitychange` for hidden tabs instead (story 010, review round 1).
- A single bad `measure:fps` row (latency 170–300 ms) can be machine load: re-run the old script from `git show HEAD:` and the new one 2× before chasing a regression (story 010).
- Keep probe-only helpers (lookup tables, counters) inside the guarded probe functions: a module-level `const` used only by the probe stays in `dist/` and check-dist can't see it (story 010 review).
- Per-frame code paths must be allocation-free when a type says so: out-parameters for helpers that return objects/tuples, index loops instead of `forEach`/`filter`/`reduce`, closures built once per effect; reviewers count them (story 010 review).
- Size a chart's axis column with an invisible in-flow copy of the widest tick label (`minmax(min, max-content)`): absolutely positioned labels don't widen a fixed column and big values (`400.000 €`) spill off-screen at 375 px (story 013).
- Element `screenshot()` crops to the element's box, so overflow looks clipped there: check real overflow with `getBoundingClientRect()` against `innerWidth` before "fixing" it (story 013).
- SVG chart styling under the token test: colours via CSS classes (also on `<pattern>` children), only `fill="url(#id)"` as attribute; `forced-color-adjust: none` + system colours on the svg so solid/stripe/hollow cues survive (story 013).
- When a design gives rules for the first and the last row, test N = 1 where both apply; the rule that keeps the end value correct wins (story 013).
- Before adding a contrast pair to an app's `tokens.test.ts`, grep `packages/platform/src/styles/tokens.test.ts`: generic pairs (e.g. muted text on `--color-surface-subtle`) are already tested there (story 014).
- When a story adds a table column or field, grep e2e for positional lookups (`td').last()`, `nth(`, exact header lists, `$`-anchored live text) and switch them to header-index lookups (story 014).
- Before making a function read precomputed values from a shared object (e.g. `projection.schedule`), grep its tests for calls that vary an input on one precomputed object: copied values would make them pass vacuously; recompute from the shared parts plus the input instead (story 015).
- When existing oracle cases are rerun for a new branch (checked option), check the branch is exercised (all 013 cases had refund 0); add one case and assert a strict difference when it applies, equality otherwise (story 015).
- Below 600 px, a label/value flex row whose label may be long needs `dt { flex: 1 1 0; min-width: 0 }`; a sub-line that must not widen its value gets `width: 0; min-width: 100%` (story 015).
- Check pure logic against story oracles directly with `node --experimental-strip-types --no-warnings --input-type=module -e "import { f } from './f.ts' …"` from the logic dir (node 25), no test file needed (story 015).
- Chromium's native unchecked checkbox border is about 4.5:1 on both surfaces under the platform's `color-scheme: light dark`; sample it from a screenshot instead of drawing an own border (story 015).
