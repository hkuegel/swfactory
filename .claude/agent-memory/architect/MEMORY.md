# architect memory

Lessons learned across stories. One rule per line, newest last. Keep under 100 lines.

- Check every AC against what the IdP/browser platform actually signals (popup gesture, iframe buttons, FedCM, 3P cookies) before designing; build an AC → mechanism table, since session/restore ACs often conflict with frontend-only constraints (story 001).
- When the ux-designer works in parallel, read their section before writing mine and answer their "open points for architect" explicitly in an "Alignment with UX" subsection (story 001).
- When blocking on one question, still deliver the full design for the parts the answer doesn't affect and isolate the variant-dependent part in one subsection, so the developer isn't stalled by a second architect round (story 001).
- Run `npx prettier --check` on every doc I edit (story, ADRs, backlog README), because `npm run verify` includes format:check over markdown and unaligned tables fail it (story 001).
- When a status cell in docs/backlog/README.md gets longer, re-run prettier on it, since the table column width changes (story 001).
- Give e2e its own dev-server port whenever the app behaves differently in e2e mode, because Playwright's reuseExistingServer silently reuses a normal `npm run dev` (story 001).
- Specify a minimal test set in the design: each AC tested once at the cheapest level that shows it (e2e per AC, unit only for reducer/pure logic), because hak found 001's 2:1 test-to-code ratio excessive (story 004).
- For dev-only code, require `import.meta.env.DEV` literally at each use site plus a `dist` grep in verify, since cross-module constant folding isn't guaranteed to strip the code (story 004).
- For UI-heavy stories, read the parallel UX section before fixing element semantics or focus model (e.g. button vs. gridcell) and follow UX there, because a11y semantics are UX-owned and the input wiring depends on them (story 005).
- Time in a pure reducer: pass `now` in the action and store timestamps in state, derive seconds in a tiny component/hook; prefer Playwright `page.clock` over a dev-only hook, so no check-dist entry is needed (story 006).
- Tie "start" events to leaving the initial phase, not to an intermediate phase: a game can end on its first reveal (ready → won) (story 006).
- Update story status with Edit, not `sed -i` (macOS BSD sed needs `-i ''`), and always run prettier --write on story + README after, since it realigns the README status column (story 006).
- For design tokens prefer light + `@media (prefers-color-scheme: dark)` blocks over `light-dark()`: e2e runs on the dev server, so a production-only CSS transform by Vite would go unseen; guard parity with a unit test over `tokens.css?raw` (story 007).
- Reduced motion via a `--duration` token set to `0s` in the media query is the primary guard; a global `!important` on `*` in index.css is only a safety net for animations and longhand transitions (story 007).
- When a design says "no `!important`" or "no X" and the UX or implementation needs an exception, write the exception into the ADR and Technical design at design time, because review had to flag the doc gap after the fact (story 007).
- Forced colours remove box-shadow and gradients: require every cell/state cue to also exist as border, outline or glyph, and test states pairwise via a computed-style signature under `emulateMedia({forcedColors:'active'})` (story 007).
- When a wrapper (panel) adds padding, any `100vw`-based fluid size formula must subtract it via shared tokens, not a literal (story 007).
- For a CSS-only visual variant (3D tilt) put `perspective()` inside the element's own `transform` and keep the DOM identical; scroller `overflow` flattens preserve-3d, and a transform needs margin compensation because only transformed bounds scroll and left/top overflow is unreachable (story 008).
- Derive geometry constants (margins, fluid-size divisors) from tilt/depth tokens in a unit test instead of trig in CSS, because Vite's CSS transform vs dev server could differ unseen (story 008).
- To re-run existing e2e flows in a variant, use a second Playwright project with `grep` + a `test.info().project.name` check in beforeEach rather than copying test bodies (story 008).
- jsdom has no `CSS.supports`: capability checks must be evaluated at mount (not module load) and be false-safe, so e2e can fake them with addInitScript (story 008).
- For a WebGL scene under an accessible DOM grid, derive the overlay CSS transform and the camera from one pure geometry module and move the camera, not the world, so the shadow map stays valid during camera motion (story 009).
- A time-varying transform on a scroll child changes scrollable overflow every frame: size its compensation margins for the whole motion range per board, or scrollbars flicker and the left edge is clipped (story 009).
- Prefer a content-sized canvas that scrolls with the overlay over a sticky viewport canvas: compositor scroll vs main-thread re-render makes tiles swim under the overlay (story 009).
- Perf or play scripts can't use `vite preview`: production has no guest sign-in or fixed mines, so run them on the dev server in mode e2e and call the numbers conservative (story 009).
- Headless Chromium (Playwright 1.64, macOS) gets WebGL2 via SwiftShader at 7–25 fps; plan e2e timing checks on a probe's manual clock, never wall clock or page.clock rAF stepping (story 009).
- Main-chunk code may import only types and three-free modules from a lazy chunk; share error identity by name constant, since importing a class value pulls the lazy module in (story 009).
- `npm install pkg @types/pkg` puts the types in dependencies; install `@types/*` with `-D` separately (story 009).
- hak's dev machine is the reference machine (MacBook Pro M2 Max): headed Playwright on it gives real GPU numbers in a spike (story 009).
- When a scene reads its look from tokens, type the palette as colours plus a numeric look record from the start and give unitless tokens parity-only checks, because UX needs per-scheme light numbers (story 009).
- For monorepo/workspace designs, spike a throwaway copy in the scratchpad (hand-made workspace symlinks, real configs) before writing the design: it exposed the missing root `workspaces` key (Vitest fs.allow), import-depth changes and spec assertions hard-wired to one app (story 011).
- A source-consumed workspace package (exports -> .ts) keeps `import.meta.env.DEV` guards droppable in the app build; prove it with a dist grep plus a control build (`NODE_ENV=development vite build --mode e2e`) that must contain the strings (story 011).
- Don't use TS project references between a source-consumed package and apps (TS6307/composite): give each workspace its own non-composite tsconfig; the app program follows imports into the package (story 011).
- When extracting shared code, grep specs and tests for app-specific assertions (headings, buttons) first: shared e2e specs need app-supplied Playwright options (title, signed-in probe), and an app title can collide with an in-app heading name (story 011).
- Order a restructuring so every step is green: scaffold (no removals), extract shared code while the old app still runs, then flip the toolchain in one commit; keep old check scripts working from the new cwd until their redesign step (story 011).
- Before extending a measurement or e2e script, replay its fixture with a small flood fill in the scratchpad: 009's fps layout A won on the first click, so the "cascade" it measured was static (story 010); for chart pixel tests, replay the real geometry modules (node runs `.ts` directly) and pick inputs where every series is ≥ 10 px visible, since an overlay segment can hide others completely (story 017).
- Make scene effects closed-form functions of elapsed time with a seeded RNG, not integrated state: the probe's manual clock, a hidden tab, a late first frame and "jump to end" then all work with no special cases (story 010).
- Pre-build every effect mesh, texture and light before `renderer.compile`: a light or material added at the click recompiles shaders; a point light stays in the scene at intensity 0 (story 010).
- In a render loop separate "board cells move" (instance rewrite + shadow pass) from "effects run" (loop alive only); one flag for both makes particle-only frames pay the full board cost (story 010).
- Camera shake only on the camera, not on the DOM overlay: any per-frame overlay translation changes the scroll bounds that the margins were sized for (story 010).
- When the UX agent edits the same story in parallel, change only my section with Edit; a scripted read-modify-write of the whole file can clobber their edits (story 010).
- When a review removes a mechanism, sweep the whole design for its name, threshold constant, label, risk line, plan step and alignment-table row, not just the cited bullet: story 010 review round 1 left six stale spots (story 010).
- In a markdown table, match a cell's text without its padding in Edit, then run prettier --write: the padded row does not match as one string (story 010).
- For process/factory stories, mind that check-structure rule 1 forbids app names in `.claude/agents|skills`, `docs/templates`, CLAUDE.md; and that `.claude/agents/*.md` is loaded as agent definitions, so a non-agent file there needs a one-time loader check (story 012).
- Scripts have no test setup: specify planted-violation dry runs in a scratchpad copy (ROOT = script's parent dir) instead of committed tests (story 012).
- For money ACs with a cent-exact oracle, recompute the oracle in the scratchpad under each rounding variant before fixing the model: 013's monthly cent rounding missed the oracle by 1 cent (story 013); recompute every number I add myself (unit-test examples) too, cents vs EUR slip easily (story 014); for a simulation oracle write two independent implementations (e.g. units/prices vs values), report each value's distance to the .5 cent boundary, and list what each rule variant would give so the tester knows the oracle tells them apart (story 016).
- Checklist T2 forbids testing an AC at two levels: put AC-listed values only in e2e (rebuild oracle) and give unit tests other inputs or an independent closed form, even if the orchestrator asks for "the oracle in unit" (story 013).
- The platform's `signedInContent` is found by role + substring name: choose a name no other label or the title contains (story 013).
- When a story adds a figure that must not change existing ones, compute it in a separate pure function fed by the existing result, not inside it: "X changes nothing else" then holds by construction (story 014).
- When a story adds a table column or field, grep earlier specs for positional asserts (`td.last()`, exact header lists, `slice`, `nth`) and list them with a header-index replacement (story 014).
- For a calculation a split-off follow-up story will make per-year, expose the per-year primitive with explicit inputs (c, Z, rate) now, but don't build the loop for it (story 014).
- When an option feeds a derived amount back into the inputs of later periods, check whether the loop touches the float state; if not, compute an integer per-period schedule first and let the float loop consume it, so the "off" path stays bit-identical (adding 0 is exact); superposition fails once the feedback changes an existing flow (story 015).
- When a computed amount joins a parsed input (c = 12·m + refund), re-check every "whole cents because it is a multiple of N" argument in ADRs and doc comments and add a rounding rule (story 015).
- When an option makes per-period values vary or moves money into a pot, grep earlier stories' UI copy for single "per year" figures and negations ("nicht im Depot") that become false, and list them for UX (story 015).
- Prefer model variants where a new tax or fee never feeds back into a balance (paid from outside or withheld from a payout): earlier figures then stay identical by construction and payout plans stay closed forms (story 016).
- Before designing machinery for a disputed rule (netting order, cost basis), check whether it changes the reported totals at all; with a flat rate it only spreads the tax over time (story 016).
- Annuity/payout formulas: use log1p/expm1 plus an explicit `rate === 0` branch; the naive (g−1)/(1−g^−n) loses ~7 digits at |q| = 1e−8 and is 0/0 at 0 (story 016).
- When a story adds a second result block, grep specs for page-wide locators: `dt` label helpers, `getByRole('region', { name })` (case-insensitive substring), page-wide `getByText` regexes, `getByRole('table'/'columnheader')`, `$`-anchored live texts; list each with its fix (story 016).
- When an SVG fill must switch between colour and a `useId` pattern by media query, pass `url(#id)` as an inline custom property on a shared ancestor and pick it in CSS; a CSS `fill` always beats the `fill` attribute and can't restore it (story 017).
- For "uniform fill" checks on stacked SVG bars with an overlay segment, scan each bar's centre column into colour runs (short runs = edges) instead of cropping rect boxes, which the overlay partly covers (story 017).
- For a build-time switch use one `VITE_*` flag compared literally (`=== 'true'`); Vite 8 folds it even when unset and drops the dead side, so spike both builds and grep both sides' strings (story 018).
- Make a mode-dependent check symmetric (string forbidden in one mode, required in the other) and pass the mode explicitly, so checking a build in the wrong mode always fails instead of loosening the check (story 018).
- Before promising "no request to X on load", find where the client is created: the GIS script loads at `createAuthClient()` in main.tsx, not on click (story 018).
- When a build gets a URL base other than `/`, grep scripts that map index.html URLs to files: a strip-leading-`/` resolver makes entry/lazy-chunk checks vacuous under a subpath (story 018).
- Pin GitHub Actions to current majors via `gh api repos/<owner>/<action>/releases/latest` (works from the sandbox); research notes and docs pages lag behind (story 018).
- For build-time prerendering (SSR build + client build + hydrate), give both builds the same `--base`: the SSR bundle bakes `BASE_URL` in, and without it links pointed to `/<app>/` (story 021).
- For a page that must work without scripts but enhance with them, switch forms via `useSyncExternalStore` with a static server snapshot: hydration matches, then the client re-renders; animate only nodes that survive the switch (story 021).
- When adding a non-app entry to `_site`, name it so the new-app name pattern can't produce it (leading `_`), and list every place that iterates `_site` dirs (`listSiteApps`, check-dist `--out`) (story 021).
