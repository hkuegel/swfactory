# reviewer memory

Lessons learned across stories. One rule per line, newest last. Keep under 100 lines.

- [Async adapter checks](async-adapter-checks.md) — Give every non-interactive await in a pending-UI flow a timeout, and check that late callbacks can't overwrite a success (story 001)
- [Build guard checks](build-guard-checks.md) — Prove the e2e-fake guard with builds that have the env ID set, plain and `--mode e2e`, into the scratchpad; read an ADR before calling it stale (story 001); probe check-dist with injected/empty/dev builds (004)
- [UI/a11y probes](ui-a11y-probes.md) — Probe forced-colours, live-region, re-render and fit-in-row claims with a scratch Playwright spec (005, 006); audit contrast by the pairs modules paint, not the design table (007); transition/viewport probe pitfalls, layer count, token-derived calc constants (008); global CSS rule = full-page PNG with/without (019)
- [WebGL scene checks](webgl-scene-checks.md) — Probe imperative controllers on every lifecycle edge (re-attach on new game) × inactive modes (forced colours); GPU leaks, per-frame cost (009); real-loop vs paused-probe gap, GL object-count leak probe, dev helpers surviving tree-shake (010); headless is always SwiftShader, gap-based bounds (019)
- Run `npx prettier --check` on the story after writing the Review: nested lists need blank lines or `verify` fails (009)
- [Test proportionality](test-proportionality.md) — hak finds suites test-heavy: flag same-AC/same-code-path duplicates as nits, ask for tests only for real uncovered risk (004); the design's test set can itself duplicate (006); size-mismatched pixel diffs pass vacuously (008); measure the real max channel noise before accepting a pixel tolerance (015)
- [Monorepo checks](monorepo-checks.md) — Skeleton isn't run by verify, fixture defaults are vacuous, probe new-app from scratchpad, avoid `git add -N` (story 011)
- Process/script stories (012): probe check-structure-style parsers on a scratchpad copy with fenced examples, bold cells and odd formats; raw-text searches (not `stripCode`d) find headings inside code fences. Don't add sections that belong to the orchestrator (Explanation) to the story.
- Calculator/logic stories (013): Node 25 runs the app's `.ts` logic directly (`node scratch.mjs` importing absolute `.ts` paths): recompute the AC oracle independently and probe worst case, tiny amounts and hostile parser input in one script before reading tests. Write the oracle in integer cents (BigInt), never EUR floats: a float oracle gave 260 false half-cent mismatches (014). For "option off = unchanged" claims, `git show main:<logic>.ts` into the scratchpad and diff JSON outputs of both versions over a sweep (015). For simulations (lots, FIFO, tax years), write the oracle in another representation (lot values instead of units/prices) and compare the raw float tax within 0,5 cent over a sweep (016).
- Check `inputMode` against each field's range: iOS `decimal`/`numeric` keypads have no minus key, so fields that allow negatives need `text` (013).
- Recount reported test numbers per workspace/project from the raw output (vitest: platform, avd, …; Playwright: chromium vs platform): a Test report mixed unit and e2e counts (014).
- Grep every spec for local helpers with the same body as another spec's (snapshot/region helpers): copies recur (014 helper file, 016 `savingSnapshot`).
- Check exact UX copy by importing the copy module in node and comparing against the story's backticked texts (regex, U+00A0 normalised); faster than reading (016).
- CSS-only look stories (017): when a forced-colours block wins only by source order at equal specificity, confirm the order also in the built `dist/assets/*.css` (byte offsets of both rules); a `var()` fill that breaks inherits black = CanvasText in forced colours, so computed-signature checks pass and only a pixel/shape assertion catches it: make sure one exists.
- Deploy/CI stories (018): job-level `concurrency` on a deploy job allows out-of-order deploys (older run deploys last); check it's workflow-level per ref. Verify action majors with `gh api repos/actions/<a>/git/ref/tags/vN`. Probe static servers with `curl --path-as-is` (`..`, `%2e%2e`, `..%2f`, `%00`, `//host/`) and `lsof` for the bind address. Write probe loops as bash scripts with arrays: zsh doesn't word-split `$CMD`.
- K8 when README/CHANGELOG come after review (docs step): mark `n.a.` with "checked before gate 2" and say so in the reply, rather than a fake pass (018).
- CI-runner stories (019): read the e2e job logs yourself (`gh run view <id> --log --job <id>`, grep `Running N tests using`, `flaky`, `failed`, `retry`): a job is green with flaky tests. Read memory lines other agents add in the diff: they can keep a recipe the story itself refuted.
- Prerendered/SSR pages (021): prove the hydration test bites by changing one word in the built `index.html` (scratch copy) and running it; compare UX copy against the built HTML with React's `<!-- -->` text separators removed; scan all of `_site/`, not only the root unit, for banned words.
- Month-unit formatters (024): check which day of the month the UI prints for a value entered as a month only, and check a test comment that claims a wording is not asserted against what it actually asserts; also ask whether an assertion can fail at all before accepting a hand value.
- Mutation tables (045): re-run them in a scratch copy outside the repository with a junction to the workspace `node_modules` (`New-Item -ItemType Junction`), so the real runner prints sites and counts; hash every file before and after each run for byte-identity. A quoted figure can be mutation-shape dependent: reproduce the count, not the string, and check which function the round trip actually calls before accepting a sign flip. PowerShell eats backticks and escaped quotes: build scratch scripts with `node -e` and single-quoted JS strings.
- Check that an assertion the Test report names exists in the file it names (`flatPartsSum([])` and `firstInvalidField` were each credited to a file that does not assert them, 045), and check a story's status against the index row for the phase the story is in, not only for equality.
- Call `node scripts/verify.mjs --mode=full --no-record` directly: through `npm run verify --mode=full` npm eats the flags as npm config, the script defaults to affected, and a recorded run makes it report "nothing to run" without running anything (045, round 2).
- Mutation figures the report quotes are shape dependent: recompute them with an independent oracle over the same inputs (micro-euro, in cents) before accepting a printed string, and hash the mutated file yourself before and after the run so byte-identity is your own observation, not only the runner's line (045, round 2).
- Make your own mutation runner print the failing assertion's file:line (vitest `--reporter=json`, the line is inside `failureMessages`): a count of red tests cannot be tied to the assertion a report names until the runner prints it (046).
- In a scratch copy, prove the run reads the copy and not the original worktree: workspace links in `node_modules` can point back, so the counts must move when only the copy is mutated (046).
- Mutate a guard by itself before accepting the assertion that credits it: a `months === 0` branch whose formula already yields 0 is dead code and its assertion cannot fail (046).
- A run that prints more failures than the mutation can move is an unstable run, not a second assertion: re-run the rule three times and name the failing specs before recording the count (046).
- Append only also means order: entries inserted before an existing entry break the Decision log even when nothing is deleted — compare the entry list of every commit that touched the story (046). Playwright's JSON reporter needs `--reporter=json`; the output-name env var alone gives nothing when the config sets the list reporter (046).
- A hand-built oracle is not an oracle: run the app's own modules (node 24 strips types, so import the real `.ts` files). My reimplementation reported 707 divergent cases that the real modules do not show (047).
- A scratch copy of `logic/` is not the test environment: `vite.config.ts` aliases the fund list to `fund-list.fixture.json` only in test mode, so a plain node run reads the committed file and the hand values move — name which data your run read (047).
- Before accepting a comment that claims "its own rounding would be X", compute X from the unrounded pieces of the whole figure: a comment said 117 where the module gives 115, and the part that actually moves was a different one (047).
- Check an equality a copy line states over a sweep, not on the one row the story quotes: `taxTotal + payout` is not `cashTotalCents` on 67 of 470 rows, each by one Cent, because the row total adds `parked` plus gross interest (047).
- Before accepting a mutation count, ask whether the guard can bind at all on the data the tests read: the sign guard was credited with 1 failed while no case has a negative increase in either data set, so its mutant prints the baseline (047).
- Mutation counts are the tester's word unless you ran them; a run that crashed before restoring the file (recovered from git) is not a count, and a cited report file that does not exist cannot be checked — ask for a re-run inside a `finally` (047).
- A mutation report can be checked against the runner's log outside the repository (byte-identity to the pre-run backup, the survivor list, the failing file:line), but a log that prints only four refs per run cannot show a count's composition, and a `finally` in a scratch script left no code to read (047 round 2).
- A hand comment's own figures must add to the total the same comment states: `31,7926` + `115,41174662135893` does not give the `147,208175` it names, and its base was a one-day slip against the real module (047 round 2).
- Check the unit of a hand value against the module: a comment read the guard-off case as `-131.875` micro-euro where the module gives `-1,318,750` µ€ — those digits are the Cent value, ten times off as micro-euro (047 round 2).
- A control line inside a case that says "rule X cannot bind here" can still be a falsifier of X: the sign-guard case's positive control is a capped figure, which is the only reading that explains the cap count moving 15 → 16 (047 round 2).
- Dropping an unmeasured CSS rule is honest when the comment names the measured number, no test asserts the value the code no longer carries, and a floor below the content minimum cannot bind; the measurement itself stays the tester's word if no browser is connected (047 round 2).
